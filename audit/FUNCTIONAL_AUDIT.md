## C. API and embedding investigation

- Selected audit provider: Gemini. Chat model: gemini-3.8-flash (application default and observed fresh browser field). Explicit audit embedding model: gemini-embedding-001, matching the user's reported setting. This is not a claim about another browser session's unseen active index.
- Authentication: real model listing succeeded using the existing project secret. The audit subprocess had no Gemini/Google key in its environment. Both model IDs appeared in the available model listing. Availability in a listing does not prove generation succeeds.
- Embeddings are remote Gemini Developer API calls, not locally installed weights. LangChain Google integration/FAISS dependencies are installed. Google SDK endpoint is the Gemini Developer API (generativelanguage.googleapis.com); vertexai=False. No third-party endpoint received the key.
- Actual dimension3072. Four controlled paper-page chunks and31long-document chunks were finite; normalized FAISS vectors had norms approximately1. Document and query requests use their respective retrieval tasks and the same frozen model. Two query results checked known paper/page facts, not just similarity magnitude.
- Index: normalized float32 vectors, faiss.IndexFlatIP. Changed embedding model requires rebuild; existing query uses original model. No semantic-to-TF-IDF fallback occurred.
- Generation: main live run returned labeled extractive fallback with a safe generic provider error. Separate minimal diagnostic used the same model/key and30-second timeout, max_retries0; result ReadTimeout. This does **not** establish the first request's exact upstream failure or prove overload/auth/quota as its cause. No random model switch/repeated paid retries were attempted.
- User's original embedding error was not reproduced: current small/31-page embedding tests succeeded. Historical root cause remains unknown; improved diagnostics will identify category and failed batch on recurrence.
- Normal client timeout120sec. Gemini LangChain max_retries1; structured repair at most one additional attempt for schema/quote failure. Ollama default localhost:11434, no authentication in app, timeout120sec,32-document batches, bounded schema repair; live service unavailable.
- Normal offline regression suite never needs a real key. Key values were not changed, printed or included in exported reports. Diagnostic scripts emit source/presence/status only.

## D. Configuration verification

See CONFIGURATION_TRACE.md for every exposed control, environment input, backend-only parameter, validation/transform/default and tested runtime value. The most consequential findings:

1. Conditional Streamlit widgets previously deleted model/URL state when hidden. Separate persistent settings now survive switches, including explicit empty inputs.
2. The threshold previously changed from0.17 to0.30 when a neural index changed slider identity/default. A stable key/default now preserves0,0.17 and other choices.
3. An index must retain its original embedding model for compatible query vectors. This was intentional, but invisible. Pending configuration is now displayed separately from active index; answer exports record execution settings.
4. Environment credentials precede secrets. Explicit empty/invalid high-priority keys now produce an error rather than silently trying a different key. The model-list helper uses the shared resolver.
5. Default model IDs seed a session once. Invalid explicit model IDs are not replaced. Chat and embedding models serve different tasks.

## G. Resume/interview findings

Demonstrably implemented: PyMuPDF page-aware parsing, configurable word chunking, hash deduplication and atomic ingestion, FAISS cosine retrieval, real Gemini document/query embeddings, LangChain structured-output chains, Pydantic schema/citation validation with bounded repair, cross-paper retrieval/UI, source exports and reproducible retrieval evaluation.

Implemented but incompletely verified: real AI cross-paper answers and structured summaries. Mocked transport tests prove orchestration/schema behavior, not current API reliability or factual accuracy. Do not claim99% formatting/factual consistency, under2sec answers, under3sec PDFs or60% review-time reduction from this audit.

Reliability limitations: citations prove quote provenance, not truth; lexical retrieval misses synonyms; top6context can miss relevant facts across many papers; summaries concatenate distinct batch findings and deduplicate exact text only, without global contradiction resolution; failed summary refresh retains old content with warning but exported schema lacks provider/model provenance. Invalid/unavailable explicit model selections remain errors.

Scalability limits: dense TF-IDF matrices (8192feature cap), flat exact FAISS search, full re-embedding/rebuild on ingestion, in-memory session libraries, sequential full-paper summaries, no OCR, durable storage, shared-library access control or individual paper removal. A full reload/restart loses collection state; server restart was not performed on the user's running session.

Honest engineering discussion: reproducing Streamlit widget-lifetime bugs; separating requested settings from active index bindings; atomic rollback on failed ingestion; compatible query/document embeddings; strict configuration precedence; bounded structured repair; secret-safe error categories; test fixtures with known facts; distinguishing mocks/live execution and provenance/factual correctness.
